h1. Publication Type taxonomy deployment and configuration

h2. 1. Upgrade eea.coremetadata

Deploy the new version of @eea.coremetadata@ and restart the backend instances.

In Plone, open:

@/admin/portal_setup/manage_upgrades@

Run the @eea.coremetadata@ upgrade step:

@6.1 -> 6.2 - Replace the generated Publication type behavior@

The upgrade:

* registers the new @publication_type@ field and catalog index;
* enables the behavior for Briefing, Report (PDF), and Web Report content types;
* removes the previously generated taxonomy field with the long name;
* configures the Publication type querystring field;
* reindexes the @publication_type@ index.

h2. 2. Verify the taxonomy

Open the taxonomy control panel:

"EEA Publication Type Taxonomy":https://demo-www.eea.europa.eu/controlpanel/taxonomies/collective.taxonomy.eeapublicationtypetaxonomy

Verify that the taxonomy is editable and contains:

* Briefing
* Report
* Corporate report
* Joint report
* Technical paper

The @publication_type@ field should be visible and required when creating or editing:

* Briefing
* Report (PDF)
* Web Report

It must not appear on other content types.

h2. 3. Run the content migration

The migration implementation is available here:

"publication_type_migration.py":https://github.com/eea/eea.coremetadata/blob/master/eea/coremetadata/browser/publication_type_migration.py

Run a dry run first:

"Publication Type migration dry run":https://demo-www.eea.europa.eu/admin/@@migrate-publication-types?dry_run=true

The dry run downloads a CSV report without modifying content.

After checking the report, run the migration:

"Run Publication Type migration":https://demo-www.eea.europa.eu/admin/@@migrate-publication-types

The migration applies the following rules:

* Briefing content is classified as @Briefing@.
* Web Report content is classified as @Report@.
* Report (PDF) content containing "EEA corporate report" is classified as @Corporate report@.
* Report (PDF) content containing ISSN @3094-5976@ is classified as @Corporate report@.
* All remaining Report (PDF) content is classified as @Report@.
* Values already present in the new @publication_type@ field are preserved.

The downloaded CSV contains the content path, URL, UID, content type, previous and final values, migration status, reason, and any error.

Review all @error@, @missing-behavior@, and @unclassified@ rows before considering the migration complete.

h2. 4. Configure the publication search block

Edit the EEA Publication Search page:

"EEA Publication Search":https://demo-www.eea.europa.eu/en/analysis/publications

In the @volto-searchlib@ block configuration:

# Open the facet configuration.
# Add or select the new @Publication type@ facet.
# Use @publication_type@ as the indexed field.
# Exclude the @Technical paper@ value.
# Save and publish the page.

h2. 5. Update Elasticsearch

A new Elasticsearch application was created for the demo website with the help of Zoltan Szabo.

Ensure that:

* @publication_type@ is included in the indexed metadata;
* the website content is reindexed after deployment and migration;
* the new field and its values are available in Elasticsearch;
* the search facet returns the expected publication results.

h2. Result

The Publication Type facet is available and functional on the "EEA Publication Search page":https://demo-www.eea.europa.eu/en/analysis/publications.

Existing Briefing, Report (PDF), and Web Report content was migrated according to the ticket rules. The resulting classifications can be verified using the CSV report downloaded from the migration script.
